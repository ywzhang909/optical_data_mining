# 温度脉动仪数据报告（ui/analysis/thermo）

把温度脉动仪（TP-1 ~ TP-16）按日分目录的原始 CSV，处理成一份中文数据报告：数据完整性、
逐探针质量、温度统计、日变化、探针一致性、脉动功率谱/结构函数，以及在接入风速后的
C_T² / Cn² 反演与设备 Cn² 交叉验证；同时分析同一数据源里的湿度、能见度、风速等环境要素。

报告以自包含 HTML 为主（图表内嵌 base64），同时落盘 Markdown 摘要、指标 JSON、清单 JSON、
全部表格 CSV，以及**随时间片的中间数据**（`slices/`，每片一份 CSV + 一份合并 Parquet），
便于下游脚本按时间片增量消费。

原始温度存在两类噪声，处理方式不同、互不替代：

* **抖动异常**（掉线、瞬时跳变、传感器错误读数）不是温度脉动，按样本剔除，不进任何统计；
* **量化噪声**（0.1 °C 量化，σ_q≈0.029 °C）无法剔除，只能在物理量里显式扣除或收窄频段。

产品平滑（滑动均值）只用于趋势图与导出表的「平滑值」列；谱、结构函数、C_T² 一律使用未平滑序列，
否则低通会抹掉惯性子区、把斜率算错。

## 1. 快速开始

```bash
# 看全部参数
uv run python -m ui.analysis.thermo --help

# 单日试跑（--max-files-per-day 控制读取量，避免一上手就解析整周 2 GB 数据）
uv run python -m ui.analysis.thermo --days 20261014 --max-files-per-day 4 --run-name try1

# 整周分析（默认读取温度 + 湿度/能见度/Cn²/风速）
uv run python -m ui.analysis.thermo --days 20261009 20261010 20261011 20261012 20261013 20261014 20261015 --run-name week42

# 只做温度、不读环境要素通道
uv run python -m ui.analysis.thermo --days 20261014 --no-aux --run-name temp_only

# 时间片改为 30 min，并关闭抖动剔除（对比用）
uv run python -m ui.analysis.thermo --slice-rule 30min --no-despike --run-name try_no_despike

# 用配置文件覆盖默认值（命令行参数优先）
uv run python -m ui.analysis.thermo --config configs/thermo_site.toml --run-name site_a
```

产物默认写入 `data/reports/thermo_<run-name>/`；`run-name` 省略时用时间戳，因此不会覆盖上一次报告。

powershell -ExecutionPolicy Bypass -File scripts\thermo_auto.ps1 -Days 20261014 20261015 -SliceRule 30min

### Python API

```python
from analysis.thermo import ThermoReportConfig, analyze, build, write_report
# 在仓库内运行时，把 ui/ 加入 sys.path 后即可 import analysis.thermo

cfg = ThermoReportConfig()                      # 或用 ThermoReportConfig.from_toml("x.toml")
result = analyze(cfg, days=("20261014",))       # 只计算、不落盘（返回 AnalysisResult）
out = build(cfg, run_name="demo")               # 计算 + 出图 + 写报告，返回报告目录

# 只要数据、自己出图/入库：
result.minute        # 分钟级长表（ts, 探针, 均值, 标准差, ...）
result.block         # 10 min 分块湍流统计
result.slices        # 时间片长表（通道 × 探针 × 时间片），即 slices/ 的内容
result.channels      # {key: ChannelResult}，含湿度/能见度/Cn² 的分钟表与统计
result.quality_overall, result.daily_summary, result.turbulence_summary, ...

# 单独把一个时间片长表落盘
from analysis.thermo import write_slices
write_slices(result.slices, Path("data/reports/custom"), cfg)
```

`analyze()` 不导入 matplotlib，可在无图形环境或测试中直接调用；只有 `build()`/`_render_figures()` 才加载绘图库。

## 2. 输入数据约定

```
data/daily_data/
└── 20261014/
    ├── Temperature/          # 必需：temperature_00.csv … temperature_23.csv
    ├── Wind/                 # 环境要素：用于 C_T² / Cn² 反演与风速统计
    ├── Humidity/             # 环境要素：相对湿度（%）
    ├── Visibility/           # 环境要素：能见度（km，仅 tp-1~tp-3 有数据）
    ├── Cn2/                  # 环境要素：设备输出 Cn²，用于交叉验证
    └── Particle/ …           # 未接入：宽表结构，需要专用解析器
```

* 所有通道共用**长表**结构：`ID,<数值>,Timestamp`，一行一个采样点，`ID` 即探针名（`tp-1`…`tp-16`）。
  因此新增一路通道通常只需在 `channels` 配置里加一行（目录名、物理范围、显示名），无需写解析代码。
* 采样率由数据自动估计（当前温度约 7.06 Hz），不写死。
* **异常码**：采集软件在缺测时写入 `1220.8`（温度/湿度）、`122.08`（风速）等固定值。温度按物理范围判无效；
  环境要素通道按各自的 `valid_min`/`valid_max`（湿度 0–100 %、能见度 0–100 km、Cn² 1e-22–1e-10）
  在分钟聚合前剔除，越界代码必然被排除。
* **截断文件**：大小恰为 10 MiB / 100 MiB 的文件视为写入过程被中断，在「文件级采样节奏与完整性」表备注列标注；
  单文件解析失败只跳过该文件（计入 `解析失败数`），不中断整批。
* 设备 Cn² 中 0 值视为缺测（越下限），不参与统计。

## 3. 处理流程

| 阶段 | 模块 | 作用 |
|------|------|------|
| 发现 | `discovery.py` | 扫描 `YYYYMMDD/通道/*.csv`，记录文件数、大小、截断线索 |
| 解析与缓存 | `ingest.py` | 分块流式读取长表 → 按时间透视成探针宽表 → 抖动剔除 → 出分钟表、分块表、谱、质量表，并按文件指纹缓存 |
| 噪声治理 | `filters.py` | 抖动掩码（偏离局部中值超阈值）、产品滑动均值、稳健 σ |
| 环境要素 | `channels.py` | 按物理范围剔除异常码 → 分钟均值 → 逐探针/逐日统计 → 时间片表 |
| 聚合 | `aggregate.py` | 跨文件/跨日统计：逐日与全时段统计、日变化、去趋势相关、瞬时离散度、湍流参数、Cn² 一致性 |
| 时间片导出 | `slices.py` | 汇总温度 + 各环境要素 + 湍流参数 → 每片 CSV / 合并 Parquet |
| 报告 | `report.py` | 生成 HTML / Markdown / JSON / CSV |
| 编排 | `pipeline.py` | `analyze()` 计算，`build()` 计算 + 出图 + 落盘 |
| 命令行 | `cli.py`、`__main__.py` | 参数解析与入口 |
| 自动化 | `scripts/thermo_auto.ps1` | 自动发现日期 + 重试 + 日志 |


### 缓存

每个原始文件的解析结果缓存到 `data/reports/.cache/<key>/`（`minute.parquet`、`block.parquet`、
`spectrum.parquet`、`quality.parquet`、`meta.json`）；辅助通道（风速/湿度/能见度/Cn²）的分钟表缓存在
`data/reports/.cache/auxiliary/`，key 里额外带上取值范围标签，避免不同物理范围的通道共用缓存。
缓存 key = sha1(文件指纹 + 影响结果的配置 + `CACHE_SCHEMA`)：

* 原始文件不变、配置不变 → 直接命中，整周重复出报告只需秒级；
* 改动 `quality` / `analysis` / `filtering` 段配置 → key 变化，自动重新解析；
* 修改缓存内容的结构（列/单位/含义）时必须递增 `ingest.CACHE_SCHEMA`，否则旧缓存会以「命中」的方式污染结果。
  当前为 **5**（引入抖动剔除，清洗后的数据与 v4 不同，升级后首次运行会全量重解析）；
* `--no-cache` 强制重解析；删除 `.cache` 目录等价于全量重算。


图表同样逐张缓存（`figures/*.png` 已存在且非空则跳过），因此中途失败重跑会一张张推进，不会重做已完成的工作。

### 时间片中间数据（`slices/`）

```
slices/
├── 20261009/
│   ├── 0000.csv … 2350.csv      # 默认 10 min 一片，UTF-8 BOM，可直接 Excel 打开
│   └── …
├── 20261010/ …
└── all_slices.parquet           # 全时段合并视图（需 pyarrow）
```

每行是一个（时间片, 通道, 探针）组合，列为：

| 列 | 含义 |
|----|------|
| `通道` / `单位` / `探针` / `时间片` | 维度：`温度`、`相对湿度`、`能见度`、`设备 Cn²`、`风速` |
| `均值` `标准差` `最小` `最大` `有效采样` | 该时间片内的原始统计（温度的标准差是分钟标准差的均值） |
| `平滑均值` | 产品平滑列的均值（滑窗默认 5 min，只用于看趋势） |
| `C_T2` `Cn2` `谱斜率` `结构函数斜率` `噪声底` | 温度行才有：该时间片内各分块的湍流参数中位数 |

时间片长度、是否写单文件、是否写 Parquet 由 `[export]` 配置或 `--slice-rule` / `--no-slices` 控制。
报告失败不影响已经写出的时间片文件；反过来，`slices/` 也可单独用 `analyze()` + `write_slices()` 生成。

## 5. 方法与判据

### 数据质量（`quality.py`）

* **无效判定**：超出 `valid_min_c`~`valid_max_c`（默认 −80 ~ 80 °C）即无效，异常码因此必然越界。
* **卡值**：读数连续不变**超过 600 s** 才判卡值。0.1 °C 量化下夜间数分钟读数相同是正常的，按采样点数判会误报。
* **尖峰**：偏离 11 点滑动中值超过 0.5 °C。卡值与尖峰**只统计、不剔除**，避免削弱真实高频脉动。
* **离群（掉线）**：与**同一时刻跨探针中值**相差超过 5 °C 的读数判为掉线/错误值，**从统计中剔除**。同址多探针瞬时离散度中位数 < 1 °C，5 °C 以上的偏离只可能是传感器故障；这类值在单探针序列里是一段"平稳值"（本站 tp-16 曾连续若干点返回 0.0 °C），滑动中值判据抓不到，只能靠横向比对。判据由 `quality.cross_probe_max_dev_c` 控制，设 0 可关闭。
* **抖动（跳变）**：偏离**本探针局部中值**超过 `despike_threshold_c`（默认 1.0 °C，窗口 5 s）的采样判为抖动，**从统计中剔除**，质量表「抖动采样」列计数。
* **量化噪声**：步长 Δ 由数据实测（默认 0.1 °C），σ_q = Δ/√12 ≈ 0.029 °C，是高频统计的固有噪声底。

### 抖动剔除与产品平滑（`filters.py`）

判据用**绝对阈值**而不是 MAD 倍数：0.1 °C 量化下 MAD 本身就接近量化噪声，按倍数判会把正常量化跳动全部
当成异常；本站真实跳变在 1 °C 量级，1.0 °C 阈值既能抓住掉线/跳变，又不动真实脉动。抖动样本置为 NaN，
与无效值、跨探针离群同样处理，因此分钟统计、谱、结构函数、C_T² 全部在清洗后的序列上计算。

阈值不是拍脑袋定的：对本批 7 天、2226 个「探针 × 文件」共 5691 万采样统计 `|T − 35 点滑动中值|`，
**99.9 分位正好等于一个量化步长 0.1 °C**，最大偏离在绝大多数文件里也只有 0.1 °C；全周只有 22 个采样偏离
超过 1 °C（全部是 tp-16 在 19–20 °C 与 0 °C 之间的跳变）。也就是说 1.0 °C 阈值零误杀，而 0.1–1.0 °C
之间没有任何真实样本，阈值放在区间内结果都一样。

产品平滑是**另一件事**：分钟长表另存 `平滑值`（居中滑动均值，默认 5 min），只进入趋势图与 `slices/` 的
`平滑均值` 列。物理量不使用平滑序列——低通会把惯性子区抹掉，平滑后再拟合斜率是错的。

### 环境要素（`channels.py`）

每路通道（湿度、能见度、设备 Cn²，以及配置里可加的任意同类通道）：

1. 读长表 → 按 `valid_min`/`valid_max` 剔除异常码与 0 值（Cn²）；
2. 聚合成分钟均值（`analysis.minute_rule`），多文件按时间拼接；
3. 出逐探针统计（含覆盖率、P05/中位/P95）、逐日统计与质量提示（覆盖率不足、探针明显偏少、贴近量程上限）；
4. 生成时间片表，与其他通道一起写入 `slices/`。

`is_reference=True` 的通道（设备 Cn²）额外作为独立参考量参与 Cn² 交叉验证。设备 Cn² 与温度反演 Cn²
来自完全独立的测量链，量级一致是反演可信的必要条件。

**已知的通道异常**（会自动写入报告「数据提示」）：

* 湿度 tp-2 / tp-4 全为异常码，无有效分钟；
* 能见度只有 tp-1~tp-3：tp-1 有约 46% 的分钟贴在其自身上限 75 km（量程封顶），tp-2 约 94% 的分钟为 0（疑似未接入或间歇失效）；
* 设备 Cn² 的 tp-6 只有约 28% 的分钟覆盖。

封顶按**探针自身观测上限**判，而不是配置的 `valid_max`：能见度实际封在 75 km、配置写的是 100 km，
用配置判永远抓不到。大量为 0 的探针保留在表格里（便于核对），但不参与通道级中位数，
避免把「未接入」当成「0 km / 0 %」。



### 脉动功率谱（`metrics.py`）

对每个 10 min 分块线性去趋势后做 Welch 功率谱，在频段内拟合 log–log 斜率，Kolmogorov 惯性子区理论值约 −5/3。
图上画的是**全时段中位谱**：每个文件的谱曲线先在各探针内取中位，再跨文件取中位（`aggregate.merge_spectra`），
否则 159 个文件、952 个频点的曲线直接叠在一起会变成一片无法阅读的噪声带。

**自动收窄频段**（`spectrum_auto_band=True`）：只保留功率高于 2 倍量化白噪声底的频段再拟合。不做这一步时，噪声段会把斜率拉平（实测会把 −0.66 抬到 −0.91），斜率失去物理意义。表格同时给出拟合频段上下限与 R²，便于判断结果是否可信。

### 结构函数与湍流参数（`metrics.py`、`aggregate.py`）

* 结构函数 D_T(τ) = ⟨[T(t+τ) − T(t)]²⟩，纵轴保留**原始值**（含量化白噪声偏置）；
* **噪声底**：白噪声在 τ→0 处给出一个平台（理论上 2σ_q²）。直接用理论值硬减会过度校正——
  本站实测 σ 只有 0.03–0.06 °C，2σ_q²≈1.67e-3 °C² 比实测的 D_T(1 s)≈1.0e-3 还大，短滞后被压成负数，
  结构函数只剩两三个点（此前的图就是这样坏掉的）。因此改用经验噪声底：用最短两个滞后按
  D(τ)=a+b·τ^(2/3) 外推到 τ→0，取截距 a，并以 2σ_q² 为上界、实测最短滞后为下限；
  每块的噪声底随分块表一起存下（`噪声底` 列）；
* 校正后 ≤0 的滞后视为被噪声主导，置为无效、不参与拟合；
* Taylor 冻结假设下 C_T² = D_T(τ) / (U·τ)^(2/3)，取拟合滞后区间（默认 2~16 s）内各滞后的中位数；
* Cn² = (79×10⁻⁶·P/T²)²·C_T²，P 取 `site_pressure_hpa`（**默认 1013.25 hPa，需按站点实际气压修改**），T 为摄氏温度 + 273.15；
* 未接入风速或风速全为 0 时，C_T²/Cn² 不反演，报告"数据提示"里明确说明。

### 短时段保护

* 分析时段不足 `min_span_hours_for_diurnal`（默认 6 h）时不出日变化节律结论，也不画平均日变化；
* 相关分析先去趋势（滑动中值窗口 `detrend_window_s`，默认 900 s，且自动限制在时段长度的 1/4 以内），避免共同日变化淹没脉动信号；时段短于 30 min 时跳过相关。

### Cn² 交叉验证

`Cn2/` 通道为设备自身输出（约 10 s 节拍），与温度反演 Cn² 完全独立。`cn2_agreement` 表给出两者的
量级比、对数偏差与相关系数，用于判断反演是否落在同一量级。`aveCn2_computed/`、`r0_computed/`
在当前数据中只有表头、无数据，因此不参与分析。

## 7. 已知限制

* **信噪比低**：原始数据量化到 0.1 °C，σ_q ≈ 0.029 °C；长时段 σ 可低至 0.03–0.06 °C，波动信噪比只有 1–2 倍。因此谱斜率、C_T²、Cn² 只能作量级参考，报告会自动给出该提示。
* **气压假设**：Cn² 反演的 P 来自配置而非实测，换站点必须改。
* **单站单设备**：反演的可靠性没有独立标定源，只能靠设备 Cn² 做量级交叉验证。
* **卡值/尖峰不剔除**：为保证脉动统计不失真，只标注不修改数据；真正剔除的只有抖动跳变与跨探针掉线。
* **能见度只有 3 个探针且数据可疑**：Visibility 通道仅 tp-1~tp-3 有数据，tp-1 大量分钟封在 75 km、tp-2 大量为 0，
  该通道的中位数只是粗略量级参考；报告会自动给出封顶与零值提示。
* **近静风时 C_T² 发散**：本站风速中位数只有 0.08 m/s，Taylor 冻结假设（C_T² = D_T/(Uτ)^(2/3)）在 U→0 时失效，
  C_T²/Cn² 的量级会偏大；报告会自动给出「接近静风」提示。取分块中位数可以压住个别极端块，但不能修正物理前提。

* **环境要素没有同址标定**：湿度/能见度/Cn² 只做统计与时间片导出，不与温度做因果分析。
* **Particle 未接入**：该通道是宽表（粒径分箱作为列），需要专用解析器，目前只在清单里记录文件数。

## 9. 故障排查

| 现象 | 处理 |
|------|------|
| `ModuleNotFoundError: analysis.thermo` | 需从仓库根目录运行，或把 `ui/` 加入 `sys.path`；CLI 请用 `python -m ui.analysis.thermo` |
| 报告没更新 | 检查 `--run-name` 是否复用旧目录，或删除 `figures/*.png` 强制重画 |
| 结果与上次不同 | 配置变了导致缓存 key 变化属正常；确认 `site_pressure_hpa`、`block_rule`、`filtering` 等是否被改；升级 `CACHE_SCHEMA` 后首次运行会全量重解析 |
| 某天数据缺失/为空 | 看 `cadence` 表的覆盖率与备注列，再看 `manifest.json` 的 `缓存文件数/解析文件数` |
| `slices/` 为空 | 检查 `[export].enabled` 与 `--no-slices`；`--no-aux` 时只有温度行 |
| 湿度/风速文件读得慢 | 单日单通道约 360 MB；首次解析写缓存后，重跑只需秒级 |
| 进程随机崩溃（Windows 无输出退出） | 与代码无关的内存不稳定；已用逐文件缓存兜底，直接重跑即可从断点继续，或用 `scripts/thermo_auto.ps1` 自动重试 |
| 中文表头在 Excel 中乱码 | `tables/*.csv` 与 `slices/*.csv` 均以 UTF-8 BOM 写出，若仍乱码请用「数据 → 自文本」并选 UTF-8 |
